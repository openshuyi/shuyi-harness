# 编码智能体框架 —— 总体架构与开发计划

> 版本：v0.1（个人版第一阶段）
> 定位：本地优先的编码 + 通用智能体，Web 页面交互，参考 OpenCode 的「本地服务端 + 浏览器客户端」形态
> 运行时：Bun

---

## 1. 设计原则（不可妥协项）

以下原则来自对 OpenCode、DeepSeek Harness、Claude Code、OpenHands、Aider、SWE-agent 等框架的架构借鉴，后续所有模块设计必须遵守：

1. **Model + Harness = Agent。** 我们构建的是围绕模型的运行时（Harness），不是「更聪明的循环」。
2. **一切皆事件，事件日志是唯一事实来源。** 模型看到的一切（系统提示、消息、工具调用与结果、审批决定、压缩动作、模式切换）全部记入 append-only 事件日志。恢复（resume）、分叉（fork）、回放（replay）、调试、未来的审计，全部操作在同一条事件流上。
3. **核心 Loop 小而固定。** Loop 只做 `提议动作 → 权限检查 → 执行 → 结果折回上下文`，不含任何业务逻辑。模式（Plan/Build）只改变工具面和系统提示，不改变 Loop。
4. **权限 fail-closed。** 默认拒绝，显式批准才放行。Loop 调用任何工具前必须经过权限服务。
5. **内核与外围分离。** 组件可以「拷贝式」借鉴（shadcn 模式），runtime（Loop、事件日志、权限、上下文工程）一律自研，不外包给任何 agent 框架。
6. **为团队版预留三个挂钩点（个人版即可「打酱油」实现，但接口必须存在）：**
   - 身份挂钩：每次工具调用携带调用者身份（个人版为常量 `local-user`）
   - 存储挂钩：事件日志与记忆的读写全部走存储接口（个人版落本地 SQLite/文件）
   - 事件挂钩：事件除写日志外走统一对外订阅接口（个人版只有 SSE 一个订阅者）
7. **简单是可辩护的架构决策。** 默认工具集刻意保持小；任何复杂度的引入必须有明确收益。

## 2. 总体形态

单机的「客户端-服务端」：Bun 常驻服务端进程 + 浏览器 Web SPA，两个进程。

- 会话独立于界面存活：关闭浏览器标签页 agent 继续运行，重开后从事件日志恢复现场。
- 未来所有入口（TUI、CI headless、桌面版）都是同一服务端的投影，不复制语义。
- 团队版路径：服务端从个人机器挪到共享主机、前面加身份层，客户端零改动。

```
┌─────────────────────── 用户机器 ───────────────────────┐
│   浏览器 (Web SPA)                                      │
│      │  HTTP + SSE（订阅事件流）                         │
│      ▼                                                 │
│   ┌─────────────────────────────────────────────┐     │
│   │        Agent Server（Bun 常驻进程）            │     │
│   │   API 层 · 会话管理 · 核心 Loop · 工具系统     │     │
│   │   上下文工程 · 权限服务 · 模型适配 · 存储       │     │
│   └──────┬──────────────┬──────────────┬────────┘     │
│          ▼              ▼              ▼              │
│      SQLite 事件日志   文件系统/仓库    LLM API / MCP    │
└────────────────────────────────────────────────────────┘
```

## 3. 服务端模块划分

按依赖方向严格分层，上层可依赖下层，反之禁止。

| # | 模块 | 职责 | 关键约束 |
|---|------|------|----------|
| 1 | API 层 | HTTP 接口 + SSE 推送，唯一对外门面 | 只做转发与序列化，不含逻辑 |
| 2 | 会话管理 | 会话生命周期：创建/恢复/分叉/删除；持有活跃 Loop 实例注册表 | 恢复 = 从日志重建上下文重启 Loop；分叉 = 复制日志到某事件点 |
| 3 | 核心 Loop | propose → permission → tool → observe 固定循环 | 无业务逻辑；Plan/Build 不在 Loop 内 |
| 4 | 上下文工程 | 组装模型输入；压缩；记忆读写；缓存前缀稳定 | 前缀逐字节稳定；填充 ~75% 触发结构化压缩 |
| 5 | 工具系统 | 内置工具、LSP 接入、MCP 客户端、工具可见性计算 | 可见性运行时计算；MCP 与内置工具同一权限模型 |
| 6 | 权限服务 | 规则匹配 + 沙箱分级 + 审批工作流 | fail-closed；独立于 Loop，Loop 强制经过它 |
| 7 | 模型适配层 | 统一消息/工具调用/流式抽象，抹平厂商差异 | 叶子接缝，可替换；Loop 不知道自己在跟哪个模型说话 |
| 8 | 存储层 | SQLite 事件日志 + 配置 + 记忆文件 | append-only；事件表是唯一事实来源 |

### 3.1 API 层接口面

- 会话操作：创建会话、发消息、中断当前轮次、切换模式/模型、分叉、删除
- 事件订阅：`GET /sessions/:id/events?after_seq=N`（SSE，支持断线续传）
- 审批响应：`POST /sessions/:id/approvals/:approval_id`（批准/拒绝/记住规则）

### 3.2 工具系统默认集（第一阶段）

`read` / `write` / `edit` / `bash` / `glob` / `grep`，共 6 个。

- 编辑用外科式增量编辑（str_replace / 行区间替换），禁止整文件重写
- 大文件分页读（带行号返回窗口）
- `bash` 默认进入审批流程

### 3.3 权限服务

- 规则示例：`read/glob/grep` 永远放行；`write/edit` 在工作区内放行（可配置）；`bash` 逐条询问
- 沙箱三级：只读 / 工作区可写（默认）/ 完全访问
- 注意：文件系统沙箱默认只限制「写」；「读」限制需显式声明敏感路径（如 `~/.ssh`）
- 审批决定本身作为事件写入日志（谁在何时批准了什么，完整入参留痕）

### 3.4 上下文工程

- 系统前缀（工具定义 + 人格指令 + 核心规则）在所有请求间逐字节一致；时间戳、会话 ID 等易变信息放最后一条用户消息
- 压缩阈值：上下文填充 ~75% 时触发，留足空间给压缩提示本身
- 压缩使用结构化模板（Session Intent / Files Modified / Key Decisions / Active Goals / Next Steps），禁止自由摘要
- 压缩前先做确定性清理：去重重复文件读取（只留最新）、删除已解决报错、截断冗长工具输出
- 长期事实（架构决策、用户偏好、环境常量）产生时立即写入记忆文件，不靠压缩时逆向提取
- 记忆文件为 Markdown 普通文件，用户可直接查看编辑

## 4. Web 客户端

定位：服务端事件流的「哑渲染器」，自身几乎无状态，刷新不丢现场。

### 4.1 页面结构

- 左侧：会话列表（进行中 / 历史 / 可搜索）
- 主区：Trajectory 视图（用户消息、助手回复 Markdown 流式渲染、工具调用卡片可展开入参/结果/耗时、文件编辑 diff、压缩与模式切换也作为事件出现在流里）
- 底部：输入框、模式切换（Plan/Build）、模型选择、中断按钮、token 用量
- 全局：审批弹窗（工具名 + 完整入参 + [批准] [拒绝] [本会话放行此规则]）

### 4.2 前端状态模型（两条数据通道）

| 通道 | 数据 | 工具 |
|------|------|------|
| 实时事件流（订阅，增量追加） | 当前会话消息流、工具调用、审批请求、token 用量 | SSE → 自研 reducer → Zustand |
| 请求-响应快照（可缓存、可失效） | 会话列表、历史搜索、模型列表、配置 | TanStack Query |

联动：收到 `turn.completed` 事件时 invalidate 会话列表查询，列表的「最后活跃时间」自动更新。

### 4.3 组件来源

- 基础组件：shadcn/ui（拷贝安装）
- AI 聊天展示组件：AI Elements 拷贝安装（只拷展示组件：`Message`、`Response`、`Tool`、`Task`、`Reasoning`、`Conversation`），拷入后数据绑定改接到自研 store；**不引入** AI SDK 的 `useChat` runtime
- 自研三个架构特有组件：审批弹窗、diff 视图、Trajectory 时间线
- 硬约束：最内层是零框架依赖的应用核心（事件 reducer、协议解析），UI 框架可换而核心不动

## 5. 一次典型对话的完整数据流

```
用户在输入框发消息
  → API 层写入 message.user 事件
  → 会话管理唤醒该会话的 Loop
  → 上下文工程组装输入（检查压缩）
  → 模型适配层流式调用 LLM
      每个流式片段 → 事件 → SSE → 客户端实时渲染
  → 模型提议工具调用 → tool.call.proposed 事件
  → 权限服务检查：
      放行 → 直接执行
      询问 → approval.requested 事件 → 客户端弹窗
             → 用户决定回传 → approval.resolved 事件
  → 工具执行 → tool.call.completed 事件（结果/耗时/diff）
  → 结果折回上下文，循环，直到模型给出最终回复
  → turn.completed 事件（含 token 用量与成本）
```

压缩触发、模式切换、会话中断走的都是同一条路：一切皆是事件。

## 6. 开发计划与优先级

原则：每一步结束都是一个「能用」的产品；安全能力建设完成前，不让 agent 真正写文件。

### P0 —— 端到端骨架（里程碑 M1：能聊、能看见流式输出）

目标：打通最小链路，验证架构假设。

- [x] monorepo 初始化（Bun workspaces）：`packages/types` / `apps/server` / `apps/web`（v0.2 起按 better-t-stack 规范：可运行应用在 apps/，共享包在 packages/）
- [x] 事件模型定义落地为 `packages/types` 类型包（见《事件模型设计》文档）
- [x] SQLite 事件日志：建表、append 写入、按 seq 读取
- [x] 单模型适配（先接一家，OpenAI 兼容协议优先）
- [x] 核心 Loop：消息 → 模型 → 文本回复 → 事件落库（此阶段工具调用可暂不接入）
- [x] 内置工具 4 个：`read` / `write` / `edit` / `bash`（暂不挂权限，全部放行——仅限本阶段）
- [x] SSE 事件推送 + 断线续传（after_seq）
- [x] 最简 Web 页面：会话列表 + 消息流 + 输入框，流式渲染
- [x] 会话恢复：杀掉服务端进程重启，会话现场完整恢复（**M1 验收标准**）

### P1 —— 安全基线（里程碑 M2：能放心让 agent 碰文件）

- [x] 权限服务：规则引擎 + fail-closed + 沙箱三级
- [x] 审批工作流全链路：approval 事件 → 弹窗 → 回传 → Loop 恢复
- [ ] `bash` 命令完整入参在审批弹窗可见
- [x] git 集成（尚未开始，P1 遗留项）：每个会话工作分支，每次写入原子提交（撤销机制）
- [x] 敏感路径读保护（`~/.ssh`、`.env` 等默认黑名单）
- [ ] **M2 验收标准**：全程不人工干预规则配置的情况下，agent 无法在工作区外写入、无法静默执行任意 shell 命令

### P2 —— 上下文工程（里程碑 M3：长任务不跑飞）

- [x] 结构化压缩（模板 + 确定性清理前置 + 75% 阈值）
- [x] 记忆文件读写工具 + 系统提示注入
- [x] Plan/Build 双模式（工具面切换 + 计划审阅）
- [x] 缓存前缀稳定性检查（前缀 hash 写入事件，可观测缓存命中率）
- [ ] **M3 验收标准**：连续 50+ 轮工具调用的长任务，压缩后任务目标不漂移

### P3 —— 能力扩展（里程碑 M4：像个成熟工具）

- [x] LSP 接入（自动探测项目语言服务器，诊断/跳转工具）
- [x] MCP 客户端（外部工具接入，同一权限模型）
- [x] 多模型适配（Anthropic / DeepSeek 等，按会话可切换）
- [x] 子代理机制（上下文隔离 + 摘要返回）
- [ ] **M4 验收标准**：接 1 个真实 MCP server 完成跨系统任务；大仓库（1 万+ 文件）中 LSP 辅助定位正确

### P4 —— 体验打磨（里程碑 M5：日常可依赖）

- [x] diff 视图（P0 已含基础版；批量编辑审阅留待后续）
- [x] 会话分叉 / 全文搜索
- [x] token 用量与成本统计面板
- [x] Trajectory 视图（P0 已含事件流渲染；按来源过滤留待后续）
- [x] Bun 编译独立二进制分发（单命令安装启动）

### 优先级说明

| 优先级 | 理由 |
|--------|------|
| P0 最高 | 事件日志与 Loop 是全局地基，定错了后面全部返工 |
| P1 次之 | 安全是「个人工具」与「玩具」的分界线；且审批事件模型影响日志 schema，越晚做迁移成本越高 |
| P2 第三 | 上下文工程决定长任务上限，是投入产出比最高的质量项 |
| P3/P4 | 属于能力广度与体验，内核稳定后随时可加，不阻塞 |

### 明确不做（个人版范围内）

- 多用户 / RBAC / 配额计费（团队版内容，但三个挂钩点必须留在接口里）
- 云端同步
- 移动端
- 插件市场（接缝先以内部接口形式存在，稳定后再开放）

## 7. 风险与对策

| 风险 | 对策 |
|------|------|
| 事件模型早期定错，日志 schema 返工 | 事件 envelope 字段宽松（payload 为 JSON），类型新增走追加而非修改；文档先行（已产出） |
| 自研 Loop 踩坑 | MastraCode 源码与「Build Your Own Claude Code」工作坊大纲作为交叉参照（结构与我们几乎逐项重合） |
| AI Elements 组件与自研 store 接线腐烂 | 只拷展示组件，数据适配集中在单一 adapter 目录，组件内不出现协议代码 |
| Bun 生态个别原生依赖兼容问题 | better-sqlite3 若有问题切换 Drizzle + libsql；CI 中加 Node 兼容性冒烟测试 |
| 上下文压缩质量不达标 | 压缩模板、阈值、确定性清理全部做成可配置；压缩前后事件完整留痕，可回放对比调优 |
