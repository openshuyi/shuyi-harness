# 编码智能体框架 —— 事件模型设计

> 版本：v0.1
> 地位：本文档是全系统第一份契约。事件模型同时决定三件事：SQLite 表结构、SSE 协议形状、前端 reducer 的形状。任何修改必须先改本文档。

---

## 1. 核心不变量

1. **唯一事实来源**：模型看到的一切必须能从事件日志完整重建。任何影响模型输入或系统状态的动作都是事件。
2. **append-only**：事件只追加，永不修改、永不删除（会话删除 = 逻辑删除标记事件 + 物理清理策略另行定义）。
3. **每会话单调序号**：`seq` 在单个会话内严格递增、无空洞（写库时由事务保证），是客户端断线续传与去重的依据。
4. **事件即投影源**：UI 回放、上下文重建、token 统计、未来的审计，全部是对同一条事件流的不同 fold，不允许有第二个事实源。
5. **演进方式**：只允许新增事件类型和新增可选字段，禁止修改已发布事件的语义。

## 2. 事件信封（Envelope）

所有事件共享同一外层结构：

| 字段 | 类型 | 说明 |
|------|------|------|
| `event_id` | string (uuid) | 全局唯一 |
| `session_id` | string | 所属会话 |
| `seq` | integer | 会话内单调递增序号（写入时由 SQLite 事务分配） |
| `ts` | integer (unix ms) | 发生时间 |
| `type` | string | 事件类型，点分命名（见第 3 节） |
| `actor` | enum | `user` / `agent` / `system` |
| `turn_id` | string \| null | 所属轮次（一轮 = 从用户消息到 turn.completed/aborted） |
| `causation_id` | string \| null | 因果上游：如工具结果指向对应的 tool call，审批决定指向审批请求 |
| `payload` | object (JSON) | 各类型自定义载荷 |

设计说明：

- **`turn_id`** 使「一轮对话」成为可查询、可统计（成本归集）的单位。
- **`causation_id`** 构成因果链，是 Trajectory 视图和调试回放的关键：从任意事件可向上追到触发它的事件。
- **`payload` 为宽松 JSON**：类型演进只动 payload 内部，信封保持稳定。

## 3. 事件类型清单（v1）

### 3.1 会话生命周期

| type | actor | payload 关键字段 | 说明 |
|------|-------|------------------|------|
| `session.created` | system | `title`, `cwd`, `mode`, `model`, `sandbox_level` | 创建即确定工作目录与初始模式 |
| `session.config_changed` | user | `mode?`, `model?`, `sandbox_level?` | 模式/模型切换 |
| `session.forked` | user | `from_session_id`, `fork_at_seq` | 分叉：新会话复制至指定 seq |
| `session.archived` | user | — | 逻辑归档 |
| `session.titled` | system | `title` | 自动标题（v1.3 新增；首轮完成后由 title 代理生成，不参与上下文重建） |

### 3.2 消息与流式输出

| type | actor | payload 关键字段 | 说明 |
|------|-------|------------------|------|
| `message.user` | user | `text`, `attachments?` | 用户输入 |
| `message.assistant.delta` | agent | `text_delta` | 流式文本片段（**可压缩**，见 4.3） |
| `message.assistant.thinking_delta` | agent | `thinking_delta` | 推理流（厂商支持时） |
| `message.assistant.completed` | agent | `text`, `thinking?`, `finish_reason` | 该条消息终稿（重建上下文以此为准） |

设计说明：**delta 事件服务于实时渲染，completed 事件服务于上下文重建**。重建算法只读 completed；delta 是渲染层优化，可丢弃。

### 3.3 工具调用

| type | actor | payload 关键字段 | 说明 |
|------|-------|------------------|------|
| `tool.call.proposed` | agent | `call_id`, `tool`, `args`, `permission_hint` | 模型提议（此时未经过权限检查） |
| `approval.requested` | system | `approval_id`, `call_id`, `tool`, `args`, `risk_summary` | 权限服务决定询问用户 |
| `approval.resolved` | user | `approval_id`, `decision`(`approve`/`deny`), `remember_rule?` | 用户决定，完整留痕 |
| `tool.call.started` | system | `call_id` | 开始执行 |
| `tool.call.output_delta` | system | `call_id`, `chunk` | 长输出分片（如 bash 持续输出），渲染优化用 |
| `tool.call.completed` | system | `call_id`, `result`, `truncated`, `duration_ms`, `side_effects?` | 结果终稿；`side_effects` 记录 diff、提交 hash 等 |
| `tool.call.failed` | system | `call_id`, `error`, `duration_ms` | 失败也是事件，折回上下文供模型纠错 |

### 3.4 上下文与记忆

| type | actor | payload 关键字段 | 说明 |
|------|-------|------------------|------|
| `context.request.assembled` | system | `prefix_hash`, `message_count`, `token_estimate`, `model` | **每次调用模型前记录完整组装信息**；prefix_hash 用于观测缓存稳定性 |
| `context.compacted` | system | `summary`(结构化模板), `covers_until_seq`, `tokens_before`, `tokens_after` | 压缩动作；`covers_until_seq` 是重建边界 |
| `memory.written` | system | `file`, `excerpt`, `reason` | 长期事实写入记忆文件的留痕 |

### 3.5 轮次与状态

| type | actor | payload 关键字段 | 说明 |
|------|-------|------------------|------|
| `turn.started` | system | `base_commit?` | 一轮开始；base_commit 为该轮开始时工作区 git HEAD（回滚基线） |
| `turn.completed` | system | `usage`(prompt/completion/cached tokens), `cost_estimate`, `model` | 正常结束，含用量 |
| `turn.aborted` | user | `reason` | 用户中断 |
| `turn.rollback` | user | `commit`, `turns_reverted?` | 工作区回滚到指定提交（v1.2 新增；只追加，不改写历史） |
| `session.status_changed` | system | `status`(`idle`/`running`/`awaiting_approval`) | 驱动客户端状态指示 |
| `error.occurred` | system | `scope`, `message`, `retryable` | 框架级错误（如模型 API 失败） |

## 4. SQLite Schema

```sql
CREATE TABLE sessions (
  session_id   TEXT PRIMARY KEY,
  title        TEXT NOT NULL,
  cwd          TEXT NOT NULL,
  mode         TEXT NOT NULL,           -- plan | build
  model        TEXT NOT NULL,
  sandbox_level TEXT NOT NULL,          -- readonly | workspace | full
  created_at   INTEGER NOT NULL,
  archived     INTEGER NOT NULL DEFAULT 0,
  forked_from  TEXT,                    -- {session_id, at_seq} JSON
  caller_identity TEXT NOT NULL DEFAULT 'local-user'  -- 团队版身份挂钩
);

CREATE TABLE events (
  session_id    TEXT NOT NULL,
  seq           INTEGER NOT NULL,
  event_id      TEXT NOT NULL UNIQUE,
  ts            INTEGER NOT NULL,
  type          TEXT NOT NULL,
  actor         TEXT NOT NULL,
  turn_id       TEXT,
  causation_id  TEXT,
  payload       TEXT NOT NULL,          -- JSON
  PRIMARY KEY (session_id, seq)         -- 会话内序号唯一且紧凑
) WITHOUT ROWID;

CREATE INDEX idx_events_type ON events(session_id, type, seq);
CREATE INDEX idx_events_turn ON events(session_id, turn_id);
```

写入约束：

- **seq 分配必须在事务内完成**：`BEGIN; SELECT MAX(seq) ...; INSERT; COMMIT;`（WAL 模式下单写者，开销可忽略）。
- 任何代码路径**不得**绕过存储接口直接写表（团队版存储挂钩依赖这一点）。

### 4.1 配置与记忆

- 全局配置、权限规则：SQLite 外的 TOML/JSON 文件（用户可手改）。
- 记忆：Markdown 文件（`~/.agent/memory/`，项目级记忆放仓库内 `.agent/memory/`），不在事件日志内，但**每次写入都有 `memory.written` 事件留痕**。

### 4.2 大 payload 策略

工具结果超过阈值（建议 32KB）时：

- payload 内存截断摘要 + `truncated: true` + 完整内容落独立文件（`blob/<event_id>.txt`），事件内记路径。
- 重建上下文时使用截断版（与模型当时所见一致）；UI 可展开查看完整版。

### 4.3 delta 事件压缩（后续优化，v1 可不做）

`message.assistant.delta` 量大（一次长回复数百条）。v1 直接全量存；后续可后台合并：消息完成后将 delta 序列折叠为单条事件。重建算法不读 delta，因此此优化对重建透明。

## 5. 上下文重建算法

输入：`session_id`。输出：可直接发给模型的消息序列。

```
1. 读取最新一条 context.compacted 事件（若无则 covers_until_seq = 0）
2. 消息序列 = 系统前缀(由上下文工程模块实时组装)
             + 记忆文件注入(实时读取)
             + compaction.summary（若有，作为一条压缩标记消息）
             + 顺序 fold covers_until_seq 之后的事件：
                 message.user            → user 消息
                 message.assistant.completed → assistant 消息（含工具调用提议）
                 tool.call.completed/failed  → tool 结果消息
                 approval.resolved(deny)  → 以 system 注记形式注入（模型需知道被拒绝及理由）
                 session.config_changed  → system 注记（模式切换影响后续行为）
                 其余事件（delta、status、统计类）→ 忽略
3. 估算 token；若超阈值，触发压缩（写 context.compacted），重算
```

要点：

- **重建结果是确定性的**：同一事件流必然重建出同一上下文（前缀与记忆除外，由 prefix_hash 留痕保证可观测）。
- **分叉的实现**：新会话复制 `covers_until_seq` 逻辑边界内全部事件 + 边界之后至 fork 点的事件，然后 append 一条 `session.forked`。物理复制行即可，数据量小。
- delta 事件绝不参与重建。

## 6. SSE 协议

```
GET /sessions/:id/events?after_seq=N
→ Content-Type: text/event-stream

data: {"event_id":"…","seq":128,"type":"tool.call.completed",…}\n\n
data: {"event_id":"…","seq":129,"type":"message.assistant.delta",…}\n\n
```

- `after_seq`：客户端重连时带上本地已见的最大 seq，服务端**先补发缺口再转入实时推送**。首次连传 0。
- 服务端实现：订阅内存事件总线 + 查询 SQLite 补洞，二者以 seq 无缝衔接。
- 心跳：每 15s 一条注释行 `: ping`，防代理断连。
- 客户端按 seq 去重（弱网重连可能收到重复尾部）。

## 7. 前端 Reducer 契约

前端 store 是事件流的 fold，与重建算法同构但面向渲染：

| 状态片 | 由哪些事件驱动 |
|--------|----------------|
| 消息列表（含流中气泡） | message.user / *.delta / *.completed |
| 工具调用卡片（pending→running→done） | tool.call.proposed / started / output_delta / completed / failed |
| 待审批队列 | approval.requested / resolved |
| 会话状态指示 | session.status_changed |
| token 用量 / 成本 | turn.completed |
| 压缩标记（UI 分隔线） | context.compacted |

reducer 必须是**纯函数**：`(state, event) => state`。这保证回放、测试、时间旅行调试成立。

## 8. 事件模型与三挂钩的关系

| 挂钩 | 在个人版的实现 | 事件模型中的位置 |
|------|----------------|------------------|
| 身份挂钩 | `sessions.caller_identity` 常量 `local-user`；每个事件的 `actor` 字段 | 已内置 |
| 存储挂钩 | 所有读写经 `EventStore` 接口（append / readRange / readSince / fold） | SQLite 是当前唯一实现 |
| 事件挂钩 | append 后同步发布到内存事件总线，SSE 是唯一订阅者 | 总线接口与 SSE 解耦，未来加审计订阅者不动核心 |

## 9. 版本演进规则

1. 新增事件类型：直接在清单追加，标注引入版本。
2. 新增 payload 可选字段：允许，旧代码忽略即可。
3. **禁止**：修改字段语义、复用事件类型表达不同含义、删除事件类型。
4. 破坏性需求（如重建算法升级）通过新事件类型 + 重建器版本号实现，旧会话用旧版本重建器回放。
