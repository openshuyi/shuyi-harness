# 编码智能体框架 —— 技术选型与仓库结构

> 版本：v0.1
> 运行时：Bun（服务端 + 包管理 + 构建分发）

---

## 1. 技术选型总表

### 1.1 服务端（Bun）

| 位置 | 选型 | 理由 / 备注 |
|------|------|-------------|
| 运行时 | **Bun** | 启动快、内置 TypeScript、单文件编译分发（`bun build --compile`）；Node 22+ 作为兼容性备选，CI 做双运行时冒烟 |
| HTTP 框架 | **Hono** | 轻、路由清晰、`streamSSE` 原生支持 SSE、Bun/Node 双运行时；只做 API 门面 |
| 数据库 | **SQLite**（WAL 模式） | 零部署、单文件、append-only 日志的天然载体 |
| SQLite 驱动 | **bun:sqlite**（首选，Bun 内置） | 备选 better-sqlite3 或 Drizzle + libsql；同步 API 对 append 写入反而直白 |
| schema/校验 | **Zod** | 工具入参 schema、事件 payload 校验；也是 MCP/AI SDK 生态的通用语言 |
| MCP | **官方 `@modelcontextprotocol/sdk`** | 不自己造协议实现 |
| LSP | `vscode-languageserver-protocol` 客户端库 | 自动探测项目语言服务器（P3 阶段接入） |
| 模型适配 | **自研薄适配层** | 定义统一的消息/工具调用/流式抽象；首版接 OpenAI 兼容协议；如嫌多厂商繁琐，可在适配层内部使用 AI SDK 的 provider 包，但**对 Loop 只暴露自有接口**，AI SDK 永远不接触 Loop、事件与权限 |
| git 操作 | `simple-git` 或直接 spawn `git` | 会话工作分支 + 原子提交（撤销机制） |
| 测试 | `bun test` | 与运行时一体 |

### 1.2 前端

| 位置 | 选型 | 理由 / 备注 |
|------|------|-------------|
| 构建 | **Vite**（纯 SPA，不用 Next.js） | 后端是自己的 Agent Server，RSC 用不上；将来可塞 Tauri 做桌面版 |
| 框架 | **React 19** | 生态最成熟 |
| 样式 | **Tailwind CSS + shadcn/ui**（拷贝安装） | 组件源码归仓库所有 |
| AI 展示组件 | **AI Elements 拷贝安装** | 只拷展示组件（Message / Response / Tool / Task / Reasoning / Conversation）；拷入后数据绑定改接自研 store；**不引入 AI SDK `useChat` runtime** |
| 实时状态 | 原生 **EventSource**（SSE）→ 自研 **reducer** → **Zustand** | 会话状态本质是事件流的 fold，纯函数 reducer 表达 |
| 快照数据 | **TanStack Query** | 只管请求-响应型数据：会话列表、历史搜索、模型列表、配置；**不管实时事件流** |
| Markdown | `react-markdown` + Shiki（代码高亮） | 纯前端渲染 |
| diff | `react-diff-view` 或 `diff` + 自研视图 | 审批与编辑确认刚需 |
| 自研组件 | 审批弹窗、diff 视图、Trajectory 时间线 | 架构特有，无现成库覆盖 |

### 1.3 明确不用

| 不用 | 原因 |
|------|------|
| Mastra / LangGraph 等 agent 框架 | 它们要拥有的 Loop/存储/流式抽象正是本架构声明自研的核心层；MastraCode 源码与其「Build Your Own Claude Code」工作坊大纲仅作交叉参照 |
| Vercel AI SDK runtime（`useChat` / 流式协议） | 协议形状与自有事件模型（审批/压缩/分叉/恢复）不匹配；仅允许在模型适配层内部可选使用其 provider 包 |
| CopilotKit 等应用层框架 | 属于「应用 + agent 逻辑层」，与本架构服务端职责重叠 |
| WebSocket | SSE 单向推送足够；审批回传走普通 POST，少一个数量级的复杂度 |
| Next.js | 无服务端渲染需求，引入只会带来约束 |

## 2. Monorepo 结构（Bun workspaces）

```
agent/                          # 仓库根
├── package.json                # workspaces 声明
├── packages/
│   ├── types/                  # ★ 前后端唯一共享物
│   │   └── src/
│   │       ├── events.ts       # 事件信封 + 全部事件类型 + payload 定义（Zod schema）
│   │       ├── api.ts          # HTTP API 请求/响应类型
│   │       └── index.ts
│   │
│   ├── server/                 # Agent Server（Bun 常驻进程）
│   │   └── src/
│   │       ├── api/            # Hono 路由：sessions / events(SSE) / approvals
│   │       ├── session/        # 会话管理：生命周期、Loop 注册表、fork
│   │       ├── loop/           # 核心 Loop（固定逻辑，无业务规则）
│   │       ├── context/        # 上下文工程：组装、压缩、记忆、前缀管理
│   │       ├── tools/          # 内置工具 read/write/edit/bash/glob/grep
│   │       │   ├── lsp/        # （P3）
│   │       │   └── mcp/        # MCP 客户端（P3）
│   │       ├── permission/     # 权限服务：规则引擎、沙箱分级、审批工作流
│   │       ├── model/          # 模型适配层：统一抽象 + 各厂商 adapter
│   │       ├── store/          # 存储层：EventStore 接口 + SQLite 实现（存储挂钩）
│   │       ├── bus/            # 内存事件总线（事件挂钩：append 后发布，SSE 订阅）
│   │       └── index.ts        # 入口：装配各模块，启动 Hono
│   │
│   └── web/                    # Web SPA（Vite + React）
│       └── src/
│           ├── core/           # ★ 零框架依赖的应用核心
│           │   ├── reducer.ts  # 事件流 fold（纯函数）
│           │   ├── sse.ts      # EventSource 封装、断线续传、seq 去重
│           │   └── adapter.ts  # 事件 → AI Elements 组件 props 的适配
│           ├── components/     # shadcn/ui + AI Elements 拷入组件
│           ├── features/
│           │   ├── trajectory/ # Trajectory 视图（自研）
│           │   ├── approval/   # 审批弹窗（自研）
│           │   ├── diff/       # diff 视图（自研）
│           │   └── sessions/   # 会话列表（TanStack Query）
│           ├── store/          # Zustand stores
│           └── App.tsx
│
└── docs/                       # 架构文档（本系列文档迁入此处）
```

两条硬约束：

1. **`packages/types` 是前后端唯一共享物**：事件模型是全系统第一份契约，类型必须同构。
2. **`web/src/core` 零框架依赖**：reducer、SSE 封装、适配器不 import React。UI 框架将来可换（参考 OpenWork 从 Solid 迁 React 19 而核心未重写的先例），业务逻辑不动。

## 3. 关键数据流接线图

```
[LLM API]
   │ 流式
   ▼
model adapter ──→ loop ──→ permission ──→ tools
                    │           │            │
                    ▼           ▼            ▼
                 ┌──────── EventStore.append ────────┐
                 │   (事务内分配 seq，写 SQLite)        │
                 └──────────────┬─────────────────────┘
                                │ 发布
                                ▼
                          bus（内存总线）
                                │ 订阅
                                ▼
                    SSE /sessions/:id/events?after_seq=N
                     （先查 SQLite 补洞，再转实时）
                                │
                                ▼
                    web/src/core/sse.ts（seq 去重）
                                │
                                ▼
                    reducer.ts ──→ Zustand store
                                │
              ┌─────────────────┼──────────────────┐
              ▼                 ▼                  ▼
        AI Elements 组件   自研审批/diff组件    TanStack Query
        (经 adapter.ts)                       (turn.completed 时
                                              invalidate 会话列表)
```

## 4. 开发环境约定

- 包管理与脚本统一用 Bun：`bun install` / `bun run dev` / `bun test`
- server 开发模式：`bun --hot src/index.ts`
- web 开发模式：Vite dev server，proxy `/api` 与 SSE 到本地 server 端口
- 类型检查：`tsc --noEmit` 在 CI 中对三个包全量执行（Bun 不做类型检查，此步不可省）
- 分发：`bun build --compile` 产出单二进制，内嵌 web 构建产物（server 直接托管静态文件，生产环境单进程）

## 5. 安装/拷贝组件操作备忘

```bash
# shadcn/ui 初始化（在 apps/web 内）
bunx shadcn@latest init

# AI Elements：只按需拷展示组件，例如
bunx ai-elements@latest add message response tool task reasoning conversation

# TanStack Query / Zustand
bun add @tanstack/react-query zustand
```

拷入后的改造纪律：

- AI Elements 组件内**不允许出现** `useChat` / AI SDK import；数据一律经 `core/adapter.ts` 注入 props。
- 组件样式微调直接改拷入的源码（这正是拷贝模式的意义），但在文件头保留来源与版本注释，便于日后对照上游升级。
